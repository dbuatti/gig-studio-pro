# RLS audit — 2026-11-27

## Summary

- Every table in the `public` schema has `rowsecurity = true`.
- Core tables (`profiles`, `repertoire`, `setlists`, `setlist_songs`, `gig_sessions`, `sheet_links`, `follows`) have owner-scoped policies.
- `setlist_songs` policies correctly derive ownership through the parent `setlists` row.
- Public sharing policies exist for:
  - `profiles` where `is_repertoire_public = true`
  - `repertoire` where the owner's profile is public
  - `setlists` where an active, unexpired `gig_sessions` row exists
  - `gig_sessions` where `is_active = true`
- `admin_emails` has RLS enabled and **zero policies** (deny-all for anon/authenticated; service role only). This is intentional/acceptable unless an admin UI needs direct access.

## Notes / follow-ups

- The public `gig_sessions` SELECT policy permits listing every active row. The app queries by code, but RLS itself does not hide codes from other anonymous users. For stronger secrecy, move access-code resolution to a `SECURITY DEFINER` RPC or edge function and remove broad public SELECT.
- The `follows` policy `Anyone can see follow counts` uses `qual = true`, which exposes complete follow rows, not just counts. If follower/followed IDs should be private, replace it with an aggregate RPC.
- Some older `ALL` policies coexist with newer per-command policies (`gig_sessions`, `sheet_links`, `follows`). They are mostly redundant but semantically identical for ownership. Clean up when convenient, after tests.

## Queries used

```sql
select c.relname as table_name,
       c.relrowsecurity as rls_enabled,
       (select count(*) from pg_policies p
        where p.schemaname = 'public' and p.tablename = c.relname) as policy_count
from pg_class c
join pg_namespace n on n.oid = c.relnamespace
where n.nspname = 'public'
  and c.relkind = 'r'
order by c.relname;
```

```sql
select tablename, policyname, permissive, roles, cmd, qual, with_check
from pg_policies
where schemaname = 'public'
  and tablename in (
    'setlists','setlist_songs','profiles','repertoire',
    'gig_sessions','sheet_links','follows'
  )
order by tablename, policyname;
```
